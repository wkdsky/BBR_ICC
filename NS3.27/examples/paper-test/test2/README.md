# Test 2: Fixed Four-Flow Scenario Matrix

This is an independent experiment directory next to `test1`. It has its own
ns-3 source, runner, scenario configuration, and analysis program. It does not
invoke or modify the Test 1 script or source.

Every run has four long-lived DQC flows. Each full scenario/controller run lasts
300 simulated seconds. The controller set is `BBR-R`, `oBBR`, `BBRv2+`,
`CUBIC`, `BBRv2-formal`, `BBRv2`, and `FBBR`.

## Run

From `NS3.27`, execute the complete matrix:

```bash
examples/paper-test/test2/run_test2.sh --jobs=4
```

For a 45-second smoke run, use:

```bash
examples/paper-test/test2/run_test2.sh --smoke --jobs=4
```

To run one named scenario, use `--scenario=BASE` (or a comma-separated list).
`--skip-build` reuses the already-built Test 2 binary.

## Scenarios

`scenarios.csv` is authoritative. The six fixed-four-flow network conditions are:

| ID | Capacity | RTT | Buffer | Purpose |
| --- | ---: | ---: | ---: | --- |
| BASE | 100 Mbit/s | 40 ms | 2 BDP | Baseline |
| BUF-S | 100 Mbit/s | 40 ms | 0.5 BDP | Shallow buffer pressure |
| BW-L | 10 Mbit/s | 40 ms | 2 BDP | Low bandwidth |
| BW-H | 1000 Mbit/s | 40 ms | 2 BDP | High bandwidth |
| RTT-S | 100 Mbit/s | 10 ms | 2 BDP | Short propagation RTT |
| RTT-L | 100 Mbit/s | 200 ms | 2 BDP | Long propagation RTT |

The access links are held at ten times the bottleneck capacity. Their delays
and the bottleneck-link delay are scaled with RTT so that `baseRtt` remains the
configured end-to-end propagation RTT.

## Outputs

All experimental output is written only below `NS3.27/results/test2`:

- `raw/manifest.csv`: authoritative list of all raw files for the invocation.
- `raw/<scenario ID>/`: per-controller CSV and JSON measurements.
- `logs/<scenario ID>/`: simulator stdout/stderr logs.
- `summary/scenario_key_metrics.csv`: primary one-row-per-scenario-controller key-metrics table.
- `summary/scenario_stage_metrics.csv`: fixed four-flow stage measurements.
- `summary/all_*.csv`: concatenated raw outputs.
- `summary/validation.csv`: schema, population, duration, and controller-matrix checks.
- `summary/METRICS.md` and `RESULTS.md`: field definitions and a readable result table.

No figures are generated by Test 2 until the plotting design is chosen.
