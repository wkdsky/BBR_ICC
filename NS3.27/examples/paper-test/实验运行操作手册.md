# paper-test 三组实验运行操作手册

本文说明如何运行 `examples/paper-test` 下的 Test 1、Test 2 和 Test 3。除特别说明外，所有命令都从下面的目录执行：

```bash
cd /home/wkd/FreqBBR/NS3.27
```

三套运行脚本都会自动完成以下工作：

1. 配置并编译对应的 ns-3 实验程序；
2. 批量运行拥塞控制算法；
3. 把原始数据和日志写入 `results/testN`；
4. 调用 Python 分析脚本生成汇总表、校验结果和实验报告。

## 1. 三个实验概览

| 实验 | 主要变量 | 单个算法/场景的仿真时长 | 标准运行规模 | 主要结果 |
| --- | --- | ---: | ---: | --- |
| Test 1 | 长流数量按 `2→4→8→16→8→4→2` 动态变化 | 1800 s | 7 个算法，共 7 次运行 | CSV 汇总、`RESULTS.md`、两组 PNG/PDF 图 |
| Test 2 | 固定 4 条长流，改变带宽、RTT 和队列 | 300 s | 6 个场景 × 7 个算法，共 42 次运行 | 场景对比 CSV、`RESULTS.md`，不生成图 |
| Test 3 | 固定 4 条长流，传播 RTT 分阶段变化 | 300 s | 1 个场景 × 7 个算法，共 7 次运行 | 阶段/切换 CSV、`RESULTS.md`、PNG/PDF 图 |

三个实验比较的算法为 `BBR-R`、`oBBR`、`BBRv2+`、`CUBIC`、形式化 BBRv2、`BBRv2` 和 `FBBR`。需要注意：

- Test 1 中形式化 BBRv2 的程序参数名是 `BBRv2-ideal`；
- Test 2 和 Test 3 中对应的参数名是 `BBRv2-formal`。

## 2. 运行前检查

### 2.1 检查基本工具

```bash
cd /home/wkd/FreqBBR/NS3.27
python3 --version
g++ --version
./waf --version
```

分析脚本使用 Python 3，并依赖 `pandas`、`matplotlib` 和 `numpy`。建议使用 Python 3.9 或更高版本。检查依赖：

```bash
python3 -c 'import pandas, matplotlib, numpy; print("Python analysis dependencies: OK")'
```

如果提示缺少模块，可在当前 Python 环境中安装：

```bash
python3 -m pip install pandas matplotlib numpy
```

ns-3.27 的系统构建依赖可参考仓库根目录的 `install_deps.sh` 和 `NS3.27/README.md`。这两个文件包含较老 Linux 发行版的软件包名称；在新系统上应按发行版提供的等价软件包安装，不要机械复制已经失效的软件包名。

### 2.2 检查脚本和 FBBR 配置

```bash
ls -l examples/paper-test/test1/run_test1.sh
ls -l examples/paper-test/test2/run_test2.sh
ls -l examples/paper-test/test3/run_test3.sh
test -r examples/CCconfig/fbbr_default.conf
```

若脚本没有执行权限：

```bash
chmod +x examples/paper-test/test1/run_test1.sh
chmod +x examples/paper-test/test2/run_test2.sh
chmod +x examples/paper-test/test3/run_test3.sh
```

### 2.3 备份已有结果

运行脚本会重新创建 `raw/manifest.csv`，并覆盖相同名称的原始数据、汇总表、报告和图片。旧目录中名称不同的文件可能继续保留，因此“旧文件仍存在”不代表它属于本次运行。

正式重跑前，建议先把以下目录改名或复制到一个新的备份目录：

```text
/home/wkd/FreqBBR/NS3.27/results/test1
/home/wkd/FreqBBR/NS3.27/results/test2
/home/wkd/FreqBBR/NS3.27/results/test3
```

每次分析应以本次生成的 `results/testN/raw/manifest.csv` 为准。

## 3. 推荐执行顺序

第一次使用时，建议按以下顺序执行：

1. 检查编译器、Python 依赖、运行脚本和 FBBR 配置；
2. 备份已有的 `results/test1`、`results/test2` 和 `results/test3`；
3. 依次运行 Test 1、Test 2 和 Test 3 的完整实验；
4. 检查日志、`summary/validation.csv` 和 `RESULTS.md`。

不要为了省时间而直接同时启动三组完整实验。每个脚本内部已经支持并行，同时启动多个脚本会增加 CPU、内存和磁盘争用，影响完成时间和运行稳定性。

## 4. Test 1：动态流数实验

### 4.1 实验内容

Test 1 使用 100 Mbit/s 瓶颈和 40 ms 基础 RTT。活跃长流数量分七个阶段变化：

```text
2 → 4 → 8 → 16 → 8 → 4 → 2
```

完整实验对 7 个算法各运行一次，每次模拟 1800 s。运行脚本固定使用 `seed=1`，不同算法的 `run_id` 为 1～7。

### 4.2 完整运行

```bash
cd /home/wkd/FreqBBR/NS3.27
examples/paper-test/test1/run_test1.sh --jobs=4
```

如果机器负载较高，可改为 `--jobs=1` 或 `--jobs=2`。`--jobs` 表示同时运行的仿真进程数，不改变仿真参数。

### 4.3 输出目录

```text
results/test1/
├── raw/                 # 每个算法的原始 CSV/JSON，以及 manifest.csv
├── logs/                # 每个算法的标准输出和错误日志
├── summary/             # 聚合指标、图数据和 validation.csv
├── figures/             # fig1a/fig1b 的 PNG 和 PDF
└── RESULTS.md           # 自动生成的可读结果报告
```

重点查看：

```text
results/test1/raw/manifest.csv
results/test1/summary/validation.csv
results/test1/summary/overall_comparison_metrics.csv
results/test1/figures/fig1a_maxbw_theory_vs_measured.png
results/test1/figures/fig1b_excess_inflight_and_queue_delay.png
results/test1/RESULTS.md
```

### 4.4 只重新分析现有原始数据

完整数据使用：

```bash
python3 examples/paper-test/test1/analyze_test1.py \
  --results-dir results/test1 \
  --manifest results/test1/raw/manifest.csv \
  --expect-full
```

Test 1 的 `run_test1.sh` 没有单算法筛选选项。正式对比应使用完整的 7 算法运行，避免手工拼接出不一致的 manifest。

## 5. Test 2：固定四流场景矩阵

### 5.1 场景配置

Test 2 始终保持 4 条长流。权威场景定义位于 `examples/paper-test/test2/scenarios.csv`：

| 场景 ID | 瓶颈容量 | 基础 RTT | 队列 | 目的 |
| --- | ---: | ---: | ---: | --- |
| `BASE` | 100 Mbit/s | 40 ms | 2 BDP | 基准场景 |
| `BUF-S` | 100 Mbit/s | 40 ms | 0.5 BDP | 浅缓冲压力 |
| `BW-L` | 10 Mbit/s | 40 ms | 2 BDP | 低带宽 |
| `BW-H` | 1000 Mbit/s | 40 ms | 2 BDP | 高带宽 |
| `RTT-S` | 100 Mbit/s | 10 ms | 2 BDP | 短 RTT |
| `RTT-L` | 100 Mbit/s | 200 ms | 2 BDP | 长 RTT |

### 5.2 完整运行

```bash
cd /home/wkd/FreqBBR/NS3.27
examples/paper-test/test2/run_test2.sh --jobs=4
```

这会运行 6 个场景和 7 个算法，共 42 次仿真。

### 5.3 只运行指定场景

单场景：

```bash
examples/paper-test/test2/run_test2.sh --scenario=BASE --jobs=4
```

多个场景使用英文逗号连接，中间不要加空格：

```bash
examples/paper-test/test2/run_test2.sh --scenario=BASE,BUF-S,RTT-L --jobs=4
```

场景名必须与 `scenarios.csv` 第一列完全一致。

### 5.4 输出目录

```text
results/test2/
├── raw/<场景 ID>/       # 各算法原始 CSV/JSON
├── raw/manifest.csv     # 本次调用实际包含的用例
├── logs/<场景 ID>/      # 各算法日志
├── summary/             # 场景汇总和 validation.csv
└── RESULTS.md           # 自动生成的场景结果表
```

重点查看：

```text
results/test2/summary/scenario_key_metrics.csv
results/test2/summary/scenario_stage_metrics.csv
results/test2/summary/validation.csv
results/test2/summary/METRICS.md
results/test2/RESULTS.md
```

Test 2 当前不生成图片。

### 5.5 只重新分析现有原始数据

完整 6 场景数据使用：

```bash
python3 examples/paper-test/test2/analyze_test2.py \
  --results-dir results/test2 \
  --manifest results/test2/raw/manifest.csv \
  --expect-full
```

如果 manifest 来自 `--scenario=...`，应去掉 `--expect-full`。

## 6. Test 3：动态传播 RTT 实验

### 6.1 实验内容

Test 3 固定以下条件：

- 4 条长流；
- 100 Mbit/s 瓶颈；
- 1,000,000 字节 DropTail 队列；
- 瓶颈容量、队列和流数量在整个实验中不变。

只有传播 RTT 每 60 s 发生一次变化：

| 时间 | 传播 RTT |
| ---: | ---: |
| 0～60 s | 40 ms |
| 60～120 s | 120 ms |
| 120～180 s | 30 ms |
| 180～240 s | 80 ms |
| 240～300 s | 40 ms |

权威参数位于 `examples/paper-test/test3/scenarios.csv`。

### 6.2 完整运行

```bash
cd /home/wkd/FreqBBR/NS3.27
examples/paper-test/test3/run_test3.sh --jobs=4
```

### 6.3 只运行指定算法

只运行 FBBR：

```bash
examples/paper-test/test3/run_test3.sh --algorithm=FBBR --jobs=1
```

运行多个算法：

```bash
examples/paper-test/test3/run_test3.sh --algorithm=BBRv2,BBRv2-formal,FBBR --jobs=3
```

可用名称为：

```text
BBR-R,oBBR,BBRv2+,CUBIC,BBRv2-formal,BBRv2,FBBR
```

名称区分大小写，逗号之间不要加空格。

### 6.4 输出目录

```text
results/test3/
├── raw/DYN-RTT/         # 各算法原始结果和 controller trace
├── raw/manifest.csv     # 本次调用实际包含的算法
├── logs/DYN-RTT/        # 各算法日志
├── summary/             # 阶段、切换、总体指标和 validation.csv
├── figures/             # 动态 RTT 响应图
├── fbbr_default.conf.sha256
└── RESULTS.md
```

重点查看：

```text
results/test3/summary/phase_metrics.csv
results/test3/summary/transition_metrics.csv
results/test3/summary/overall_metrics.csv
results/test3/summary/validation.csv
results/test3/figures/dynamic_rtt_response.png
results/test3/RESULTS.md
```

### 6.5 只重新分析现有原始数据

```bash
python3 examples/paper-test/test3/analyze_test3.py \
  --results-dir results/test3 \
  --manifest results/test3/raw/manifest.csv
```

## 7. 通用运行参数

| 参数 | 适用实验 | 含义 |
| --- | --- | --- |
| `--jobs=N` | Test 1/2/3 | 最多同时运行 N 个仿真进程；必须是正整数 |
| `--skip-build` | Test 1/2/3 | 跳过配置和编译，直接复用已有的对应实验二进制 |
| `--scenario=ID[,ID...]` | Test 2 | 只运行指定场景 |
| `--algorithm=NAME[,NAME...]` | Test 3 | 只运行指定算法 |

只有在以下条件都满足时才使用 `--skip-build`：

1. 对应实验程序已经成功编译；
2. C++ 源码和 DQC 头文件自上次编译后没有变化；
3. 当前 build 目录与源码相匹配。

如果只修改了运行时读取的 `examples/CCconfig/fbbr_default.conf`，通常可以复用二进制；但必须把配置版本或哈希与结果一起保存，避免混淆不同配置的实验。

示例：已成功构建 Test 2 后跳过编译：

```bash
examples/paper-test/test2/run_test2.sh --skip-build --scenario=BASE --jobs=4
```

## 8. 长时间运行建议

完整实验建议在 `tmux` 中运行，以防 SSH 或终端断开：

```bash
tmux new -s freqbbr
cd /home/wkd/FreqBBR/NS3.27
examples/paper-test/test1/run_test1.sh --jobs=4
```

按 `Ctrl-b`，再按 `d` 可退出会话而不停止实验；恢复会话：

```bash
tmux attach -t freqbbr
```

也可以把驱动脚本输出重定向到单独文件。每个仿真本身的详细输出仍会保存在 `results/testN/logs`：

```bash
nohup examples/paper-test/test1/run_test1.sh --jobs=4 > test1-driver.log 2>&1 &
```

## 9. 结果完整性与可复现性

正式结果至少应同时保存以下内容：

1. `raw/manifest.csv`；
2. `raw` 下 manifest 引用的全部 CSV/JSON；
3. `logs`；
4. `summary/validation.csv`；
5. `RESULTS.md` 和图片；
6. 使用的 Git 提交号；
7. `examples/CCconfig/fbbr_default.conf` 或其 SHA-256；
8. 完整运行命令、Python 版本和编译器版本。

记录版本信息：

```bash
git rev-parse HEAD
python3 --version
g++ --version
sha256sum examples/CCconfig/fbbr_default.conf
```

筛选运行需要特别注意：

- Test 2 的 `--scenario` 会让新 manifest 和汇总报告只包含选中的场景；
- Test 3 的 `--algorithm` 会让新 manifest、汇总报告和图片只包含选中的算法；
- 目录中可能仍残留上一次完整运行的其他原始文件，但分析器不会把未列入新 manifest 的文件视为本次结果；
- 论文最终汇总前，应重新执行完整矩阵，或者使用经过人工审计的完整 manifest。

## 10. 常见问题

### 10.1 `Missing experiment binary`

原因通常是使用了 `--skip-build`，但对应二进制不存在。去掉 `--skip-build` 重新运行。

### 10.2 编译器不兼容

先使用系统默认 GCC。若 ns-3.27 因新编译器兼容性失败，而系统已安装 GCC 5，可显式指定：

```bash
CC=gcc-5 CXX=g++-5 examples/paper-test/test1/run_test1.sh --jobs=1
```

Test 2 和 Test 3 的用法相同。不要在没有安装对应编译器时直接照抄该命令。

### 10.3 `ModuleNotFoundError`

确认运行脚本所调用的 `python3` 与安装依赖时使用的是同一个环境：

```bash
command -v python3
python3 -m pip --version
python3 -c 'import pandas, matplotlib, numpy'
```

### 10.4 `Missing FBBR configuration`

确认文件存在且可读：

```bash
ls -l /home/wkd/FreqBBR/NS3.27/examples/CCconfig/fbbr_default.conf
```

### 10.5 某个算法运行失败

脚本会在终端打印失败日志的末尾。完整日志位于：

```text
results/test1/logs/
results/test2/logs/<场景 ID>/
results/test3/logs/DYN-RTT/
```

定位最近修改的日志：

```bash
find results/test1/logs results/test2/logs results/test3/logs \
  -type f -printf '%T@ %p\n' 2>/dev/null | sort -nr | head
```

修复问题后可以用相同命令重跑；已有同名结果会被覆盖。三套脚本没有通用的断点续跑选项。

### 10.6 分析校验失败

不要只看图片或单个 CSV。依次检查：

1. `raw/manifest.csv` 是否包含预期的全部行；
2. manifest 引用的文件是否都存在且非空；
3. 对应算法日志是否正常结束；
4. `summary/validation.csv` 中失败的检查项；
5. 当前运行是否错误地混用了筛选数据、历史残留数据和完整数据。

### 10.7 字体警告

Test 3 和 Test 1 的论文重绘脚本会优先使用 Times New Roman。系统没有该字体时，Matplotlib 可能输出字体回退警告；这通常不影响数据计算，但正式出图前应检查版式和字体是否符合论文要求。

```bash
sed -n '1,120p' results/test2/summary/validation.csv

```

并阅读：

```text
results/test1/RESULTS.md
results/test2/RESULTS.md
results/test3/RESULTS.md
```
